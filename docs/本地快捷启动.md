# 岗查查本地快捷启动

日常地址为 <http://127.0.0.1:43128/>，服务仅监听本机。当前本地源码与公开网站第 5 版功能同步：三个页面、前两页顶部可收起地图、实名名单和对比弹窗；内部岗位关联编号在前端隐藏。

## 桌面入口

桌面“岗查查”通过 Windows GUI 程序 `wscript.exe` 调用 `桌面启动.vbs`，再以隐藏窗口方式运行 `桌面启动.ps1`。入口与后台服务不显示终端窗口；启动失败仍有错误提示和日志。首次创建或修复入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\创建桌面快捷方式.ps1
```

正常使用双击桌面“岗查查”或项目中的 `桌面启动.vbs`。VBS 使用 UTF-16LE BOM 编码，以便 Windows Script Host 正确读取中文路径。`启动系统.cmd` / `启动系统.ps1` 保留为开发入口，日常启动无需打开开发终端。

## 安装与更新

需要 Node.js 22.13 或更高版本、npm 10 或更高版本，推荐项目验证过的 Node.js 24。首次安装或依赖变更后：

```powershell
npm ci
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\更新本地版本.ps1
```

更新脚本先校验冻结公开数据、构建并初始化运行环境，将浏览器资源与 Worker 放入新的 `.local-runtime` 发行目录，再原子切换 `current.json`。失败时保留既有版本指针，旧发行文件保留。正在运行的服务仍加载旧版，需重启本地服务或电脑后生效；仅更新源码不会替换运行中的版本。

正常构建使用 `scripts/validate-public-data.mjs`，不读取内部原始数据、匿名密钥，也不自动采集新年度。旧 `scripts/build-public-data.mjs` 是已被默认禁用的历史匿名生成器，不能用来更新当前实名分片。

## 运行方式

桌面入口加载 `.local-runtime/current.json` 指向的构建版本，由 Node.js 启动 Miniflare 执行 Worker。D1 在 `.local-runtime/state/d1` 中持久化 AI 请求计数及随机并发租约，跨发行版本继续使用，沿用公开版的限流和安全响应头；数据库不保存 Key、筛选条件和人员名单。日常启动不运行 Vite HMR 或重新构建。

如需在终端直接运行当前 `dist/` 构建，可执行：

```powershell
npm run build
npm start
```

`npm start` 对应 `node scripts/local-server.mjs --dist`，不依赖已准备的 `current.json`，首次启动自动创建本地 D1 并执行迁移。迁移按文件名与 SHA-256 登记，重复启动不会重复建表或清空配额；已执行迁移被改写时拒绝启动。监听端口依次读取 `GANGCHACHA_PORT`、`PORT`，均未设置时使用 `43128`；服务仍只绑定 `127.0.0.1`。请勿同时启动两个占用相同端口的版本。

普通使用请保留 `.local-runtime/state/d1`，不要通过删除它重置配额。测试可使用 `GANGCHACHA_STATE_PATH` 指向独立状态目录，避免污染日常计数。

开发调试仍用 `npm run dev` 或 `启动系统.ps1`，通常访问 <http://localhost:3000/>。AI 需要可用的 DB 绑定和配额表；未初始化的开发数据库可能使 AI 暂不可用。用完整更新脚本准备的发行版或已初始化的 `npm start` 环境进行 AI 验收，岗位查询无需 AI Key。

## 检查与故障定位

健康接口为 <http://127.0.0.1:43128/__gangchacha_health>。启动器以 `app: gangchacha` 和兼容的 `version: 1` 识别服务，实际构建版本查看 `release` 字段。版本指针更新后可据此核对服务是否已重启。

入口最多等待 15 秒；端口冲突、准备版本缺失或进程提前退出会提示错误。后台服务标准输入、输出和错误流与启动器隔离，避免后台进程拖住桌面入口。

诊断文件为 `桌面启动.log`、`启动服务.log`、`启动服务错误.log`。日志、本地 D1 状态、`.local-runtime` 和 `work/` 不上传 Git。

准备发行版后，可运行：

```powershell
node --test tests/local-launcher.test.mjs
```

测试检查冷启动、首页、静态资源、岗位分片目录、地图资源、本地 API 校验、响应头、配额持久性和端口冲突；不调用真实付费模型。没有准备本地发行版的环境会跳过桌面专用测试。完整验证另运行 `npm test`。

本轮仅同步本地与 GitHub；未更新远端 Ubuntu 服务、DNS 或 Sites 身份。原 Ubuntu 使用的 Node 启动方式在新版本中改为本地 Worker 模拟运行入口，远端部署前须验证 Miniflare、持久化目录权限和反向代理兼容性。
