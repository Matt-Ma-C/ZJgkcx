# 本地数据维护

当前本地与公开网站第 5 版使用相同的**实名冻结公开数据**。正常构建校验已经批准的文件，不从内部原始汇总重新生成，不自动下载官方附件或采集新年度。

## 正常构建与校验

```powershell
npm run data:validate
npm run build
```

`npm run build` 先执行 `scripts/validate-public-data.mjs`，再构建页面与 Worker。校验以 `scripts/public-data-manifest.json` 为固定清单，检查公开数据的文件集合、字节数、SHA-256、版本、岗位顺序、姓名与岗位/名单环节/行序的映射及允许披露字段。普通构建不读取 `work/data-private/`、内部备份或匿名密钥。

公开数据目录包含：

- `public/data/jobs-index.json`：摘要分片目录和元数据；
- `public/data/jobs.json`：与上述目录字节一致的兼容入口；
- `public/data/jobs-summary/`：7 个摘要分片，共 14,200 个岗位；
- `public/data/jobs-details/`：36 个年度与城市详情分片；
- `public/data/data-coverage.json`：年度与地区收录覆盖。

目录入口不包含完整 `jobs` 数组，也不能作为原始汇总输入。前端 `loadJobIndex` 重建全部岗位摘要后进行查询、地图、统计与导出；`loadJobDetail(job, signal?)` 在打开详情时按需加载对应详情分片，验证版本与记录关联。

## 当前姓名与关联规则

详情保留政府公开名单中的来源姓名，使用 `nameStatus` 区分 `public`、`source-masked` 和 `source-missing`。来源已脱敏或未提供姓名时保持原状态，不推测补齐；特殊字形也不猜测替换。姓名变更须保留岗位、名单环节和行序映射并重新核验。

原准考证号、性别、学校或工作单位不发布。内部岗位关联仍使用同岗 HMAC 标识，用于匹配面试成绩与已收录录用记录；该标识在前端隐藏，既非官方准考证号，也不影响“已录用”标记。AI 统计、Markdown 和 CSV 不携带人员姓名或内部关联编号。

完整原始汇总的字节一致备份与关联密钥保存在被忽略的 `work/data-private/`。不得提交、复制到 `public/` 或上传。原 SHA-256 与旧公开版本保存在内部 manifest 及历史审计中；本次同步没有改写内部原始备份、密钥或既有审计登记。

## 旧匿名生成器的保护

`scripts/build-public-data.mjs` 保留旧匿名格式的历史实现。它会生成匿名姓名和旧的未分片摘要，可能覆盖当前实名分片，**不属于当前构建流程**。

脚本在创建目录或读取任何私有资料前检查 `GANGCHACHA_ALLOW_LEGACY_ANONYMIZED`，默认非零退出并说明原因。仅在隔离的历史维护副本中，明确需要重建旧匿名版本时才可显式设为 `1`；这项开关不代表当前数据迁移流程兼容。不要在当前发布工作目录运行旧生成器，也不要把现有公开目录当原始输入。

## 新数据与修订

新增年度、替换汇总或修正名单是独立的数据迁移任务，应先归档各来源版本、核实官方来源与匹配依据，再生成与当前 schema 兼容的摘要和详情分片，复核成绩、人数、顺序及披露范围，最后更新公开锁文件并运行完整测试。更改锁文件本身不构成来源核验。

`score-provenance.json` 保留人工核验的官方计分依据登记。当前登记为空，所有成绩口径仍为未知或待复核；仅编辑登记不会自动修改冻结公开数据。后续经核验的修订需同步到对应分片并重新锁定版本。

可按岗位 ID 登记 `scoreProvenance`，完整依据应包含 `status: "verified"`、`scoreType`、`maximum`、`subjects`、`conversionRule`（没有折算也应明确说明）、`comparisonKey`、`officialSourceUrl` 和 `sourceVersion`。比较键必须反映真实一致的计分口径，不能仅依据分布或考试大类设定。修订另记 `revisionNote`；已有异常解除复核须有 `reviewResolved: true` 和官方依据。算法还需满足样本与覆盖要求，才能允许成绩比较。

当前官方 URL、发布日期、采集日期、原表行号及实际匹配过程仍待逐项补证，未知字段明确为空或待复核。原始汇总生成日期为 2026-07-27，公开数据 `dataCutoff` 未确认；维护日期不是官方数据截止日期。

状态区分已收录、未收集、关联失败、待复核，以及将来有明确官方依据才能采用的“未公布”。未收集不能自动解释为未公布，收录人数等于招录计划也不能证明名单完整。28 个同岗区间异常仍是回查线索，不能据此认定计分或关联错误。

本目录 `数据核验记录_2026-10-19.md`、`data-audit.json` 和既有登记作为当时的历史记录保留，其中对旧匿名版本及旧构建流程的说明不代表当前操作步骤。新的维护结论应另作版本记录，不覆盖历史。

## 验证与运行更新

数据修订后依次运行 `npm run data:validate`、`npm run typecheck`、`npm run lint`、`npm test`，检查目录/详情一致性、姓名映射、内部关联、口径隔离、低覆盖处理及导出范围。需要更新桌面快捷版时，再执行 `更新本地版本.ps1`，重启服务并核对首页与健康接口的 `release`。

数据构建或运行版本更新不会自动提交、推送 GitHub、更新 Sites 或部署 Ubuntu。部署身份、DB 绑定和本地运行状态分别维护，不通过复制公开数据改变。
